## fetch first
### 何が起こっているのか
「fetch first（先に取ってこい）」<br>
GitHub上のリポジトリ（リモート）の歴史が、あなたのパソコン（ローカル）よりも進んでしまっています。<br>
だから、まずはGitHub上の最新情報をあなたのパソコンに取り込んで（fetch/pull）、足並みを揃えてから、アップロード（push）してください。<br>
（例：GitHub上で直接READMEを編集したり、別のPCからPushしたりした場合によく起こります）

### 解決手順
1. GitHubの変更を取り込む（Pull）<br>
git pull origin main<br>
2. 再度プッシュする<br>
git push origin main<br>

## non-fast-forward
git pull がうまくいかなかった！<br>

### 解決手順
1. 強制的に歴史を結合する<br>
git pull origin main --allow-unrelated-histories <br>

## pushエラー以外で発生した問題集

### 歴史がふたつある...
- Need to specify how to reconcile divergent branches.<br>
→ --no-rebase　を追加して、関係ない履歴もマージしていいよ　という指定をする。<br>

### コンピュータも葛藤とかするんですね
- CONFLICT (content): Merge conflict in README.md<br>
- Automatic merge failed; fix conflicts and then commit the result.<br>

コンフリクト（競合）が起こっている状態。どっちのファイルをを残せばいいか決めてほしいと言われているらしい。<br>
当該ファイル（この場合はREADME）を開くと、丁寧に変更点を示してくれているのでどちらを採用するか決める。<br>

### マージ終わってなかった
- fatal: Exiting because of unfinished merge.<br>
コンフリクト解消の作業が終わっていないのにaddしようとしたためエラーに。<br>
解決方法は、すべての変更を解決済みとしてセットすること。<br>
よってターミナルにはgit add .と打ち込む。<br>
commit, pushで完了！！<br>

### もし画面が変わったら
Vimが開いている。解決方法は:<br>
Esc→:wq と入力→Enter

### 書きかけのファイルが残っているとき
Vimから次のような警告が出た。<br>
Swap file "絶対パス" already exists!<br>
(O)pen Read-Only, (E)dit anyway, (R)ecover, (D)elete it, (Q)uit, (A)bort: <br>
古い一時ファイルを(D)で削除し、Esc→:wq→Enterでコミット完了。<br>
