## fetch first
### 何が起こっているのか
「fetch first（先に取ってこい）」<br>
GitHub上のリポジトリ（リモート）の歴史が、あなたのパソコン（ローカル）よりも進んでしまっています。<br>
だから、まずはGitHub上の最新情報をあなたのパソコンに取り込んで（fetch/pull）、足並みを揃えてから、アップロード（push）してください。<br>
（例：GitHub上で直接READMEを編集したり、別のPCからPushしたりした場合によく起こります）

### 解決手順
1. GitHubの変更を取り込む（Pull）<br>
git pull origin main
2. 再度プッシュする<br>
git push origin main

## non-fast-forward
git pull がうまくいかなかった！

### 解決手順
1. 強制的に歴史を結合する
git pull origin main --allow-unrelated-histories 

### ここで問題発生
- Need to specify how to reconcile divergent branches.
→ --no-rebase　を追加して、関係ない履歴もマージしていいよ　という指定をする。

### コンフリクト
- CONFLICT (content): Merge conflict in README.md
- Automatic merge failed; fix conflicts and then commit the result.

コンフリクト（競合）が起こっている状態。どっちのファイルをを残せばいいか決めてほしいと言われているらしい。

当該ファイル（この場合はREADME）を開くと、丁寧に変更点を示してくれているのでどちらを採用するか決める。

### マージ終わってなかった
- fatal: Exiting because of unfinished merge.
